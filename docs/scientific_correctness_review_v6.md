# oo_v1 Reverse-GNSS Simulation — Scientific Correctness, Completeness & Value Validation (v6)

**Branch:** `feature/scientific-correctness-v2` (HEAD `fbb9f6c`, working tree clean; the sub-toggle + `config/realism.json` externalisation of commit `8c4db06` and the strapdown-gyro/MEKF IMU work of `c44b9f5` are in).

**Method.** Ten independent auditor agents (KF logic, error-chain double-count, truth↔estimation separation, orbit propagation, IMU/nadir, reference-PDF cross-check, and four value-validation sweeps) read the actual code and cited `file:line`; every correctness-critical finding was then re-read by a second adversarial agent that defaulted to *refuted* unless it could confirm from the code. The value inventory below (90 parameters) is **read from the code, not invented** — each row carries its `cfg` path and `file:line`. Reference sources are the extracted PDFs (JOW clock dissertation Table 2.1, Kaplan & Hegarty, the multi-way/two-way time-transfer papers) plus standard texts.

**Relationship to v1–v5.** v1–v3 established internal correctness (no double-count; clean truth/estimate separation; correct KF math). v4 was the realism audit; v5 validated every value and named the observability wall. **v6 re-verifies all of that on the current code and adds three dimensions v1–v5 never covered: the Kalman-filter *logic re-proof*, the *orbit propagator*, and the *IMU / attitude / nadir-pointing* path** — the last of which produces the single most actionable finding in this pass.

## 1. How to read the value tables (§2)

Each row is one tunable number, read from the code:

- **Default** — the value resolved by `masterConfig()` with `cfg.realism.grade=false` (what a plain `run_oo_v1` uses; the frozen idealised/headline goldens pin these).
- **Realism-grade** — the value under `cfg.realism.grade=true` (→ `realismGradeConfig.m`, numeric params now in `config/realism.json`), or "same" where the grade does not touch it. Individual effects are now switchable via `cfg.realism.include.<effect>` (all default true).
- **Conservative bound** — the pessimistic/realistic value and *why*. Per the standing directive, when in doubt this is the side to prefer.
- **Optimistic bound** — the best-case value and why (usually the idealised/oracle end).
- **Source** — the citation (JOW Table 2.1, Kaplan & Hegarty, IERS/IGS, Montenbruck & Gill, Ashby, Wertz, Groves, Bar-Shalom, …), or an explicit note where the number is an engineering choice rather than a literature value.
- **Plain-language effect** — what happens to the result if you raise/lower it.

"Inert" in a cell means the parameter exists in config but the active code path does not consume it in the stated grade (a completeness gap, flagged in §4/§7).

## 3. Kalman-filter logic — audit result

**Verdict: the EKF math is correct.** Every property was re-derived against the code and the high-level claim was independently re-confirmed.

- **Predict / update.** The prior `Pminus = obj.P` is explicitly saved (`ReverseGNSSEKF.m:397`) and used for `S`, `K`, and the posterior. Gain is right-division `K = Pminus*H'/S` (`:407`); NIS is `nu'*(S\nu)` (`:485`) — **no explicit matrix inverse anywhere**. Covariance propagates `F*P*F'+Q` then symmetrises (`:376-377`); the Joseph posterior `IKH*Pminus*IKH' + K*R*K'` (`:414-415`) is the numerically-stable form.
- **MEKF (quaternion error-state).** All six touch-points share one convention — local body-frame right-multiplicative error `q_true = q_nom ⊗ δq(δθ)`: nominal-quaternion body-rate propagation (`½ q⊗ω`, `AttitudeErrorStateKinematics.m:94-97`); error-state `F(θ,θ)=I-[ω×]dt`, `F(θ,ω)=I·dt` (`:704-705`); right-multiplicative injection (`:78`); **first-order covariance reset `G=I-½[δθ×]` applied to the posterior** (`:430-436`); the measurement Jacobian perturbs `C_nom·Exp([±δθ×])` in the *same* body frame (`LinkGeometry.finiteDiffAttitudeJacobian`, QES branch); and the NEES error metric uses `dC = C_nom'·C_tru → vee` (`:556-559`). This mutual consistency is the thing most MEKF implementations get subtly wrong; here it is right.
- **Gyro-bias states.** With `ω = ω_gyro − b_g`, the coupling `F(θ,b_g) = −I·dt` (`:709`), `F(θ,ω)=0` (`:710`), `F(b_g,b_g)=I`, and the ARW/RRW `Q` blocks with the optional Van-Loan cross `Q(θ,b_g) = −½·σ_rrw²·dt²` (`:865-866`) all carry the correct sign and magnitude.
- **Numerics.** Relative-tolerance eigenvalue PSD check with `nearestSPD_` projection and a diagonal float-dust nudge (`:466-482`, `:1353-1359`).

**The one substantive item — L1 (low):** on the strapdown-IMU path the ω-state *mean* is overwritten each predict with `ω_gyro − b_g`, yet `F(ω,ω)=I` and `Q(ω,ω)=σ_aa²·dt` are left in place, so `P(ω,ω)` grows without bound as an unobserved random walk while its mean is pinned to the gyro. Because `F(θ,ω)=0` decouples it from the attitude error, this corrupts **nothing** in position/clock/attitude/bias — it only makes the *reported* ω uncertainty diverge. Default OFF. **Fix (V6-4):** on the IMU path freeze ω (`Q(ω,ω)≈0`) or drop the ω state from the strapdown parameterisation. (Two cosmetic notes: the attitude H rounds the nominal quaternion through Euler before re-building the DCM — numerically fine, loses the quaternion's gimbal immunity only at the H-build boundary; and the legacy Euler-path Jacobian was symbolically re-derived and is correct.)

## 4. Error chain — double-counting & truth↔estimation separation (both re-verified clean)

### 4.1 Double-counting — CLEAN
Every physical error is represented **exactly once in truth, at most once in `h`, at most once in `R`**, and the two "estimate-and-also-charge-R" risks are each closed by a verified guard:

- **Tower-clock product σ** reaches `R` through five sinks (code diagonal, L2 diagonal, IF rebuild, shared-tower off-diagonal block, Doppler drift, carrier drift). `maskStateTowerSigma_` (`CodeMeasurementBuilder.m:696-717`) zeroes the product σ on **every** sink for any tower whose clock is a free EKF state — so its variance is never in both `P` and `R`. Default `estimateTowerClocks=false` makes the guard a no-op (golden-identical); it matters only under state augmentation.
- **Ionosphere-free `R` rebuild** (`:501-572`) strips the correlated/cancelled variance (trop, 1st-order iono, HO iono, tower-clock, hardware delay) out of the independent remainder, then re-adds each at its correct IF gain — 1st-order iono at **exactly zero**, HO iono at survival gain `(α+β(f1/f2)³)²`, trop/tower/hardware at unit gain. `α+β=1` and `α/f1²+β/f2²=0` make this exact. The most carefully-built part of the chain.
- **Atmosphere** (trop/iono): one truth bias, one model correction, one `R` σ. When the slow component is promoted to an EKF state (`perTowerZwd`/`perTowerSlant`), `R` is deliberately reduced to the fast un-trackable residual `σ_ss·√(1−e^(−2dt/τ))` so the same variance is not both estimated and charged (`ErrorChain.m:451,614`).
- **Multipath / scintillation / thermal:** injecting the realised (unknown-to-estimator) value in truth while charging its steady-state variance in `R` (with `model=0`) is the *correct* Kalman treatment, not a double-count.
- **Geometric/deterministic biases** (survey, PCO, tide, EOP, Sagnac, Shapiro, relativistic clock): each enters `z` once via the corrected geometric range or the clock bias, `h` once, with no separate `R` inflation; survey/PCO "diagnostic" copies are never re-added; Sagnac is *skipped* when iterative light-time already rotates the tower (an explicit anti-double-correction guard, `RangeCorrections.m:108-112`).

**Two low nuances, both in the *conservative* direction:** inter-frequency DCB is **inert** — hardware delay is non-dispersive and the realism `L1/L2` DCB values do nothing on the active path (L7 → V6-6); and the raw-dual-frequency L2 iono `R` σ is charged at the L1-level (over-charge), making the filter slightly *under*-confident. Neither is a double-count.

### 4.2 Truth ↔ estimation separation — INTACT
- `z` is built **only** from truth (`asset.r_ecef_m`, `asset.attitude_euler_rad`, `asset.clock.getBiasMeters()`, true tower clocks, `errorChain.truthTotal_m`); `h`/`H` **only** from the EKF state and model-side corrections (`CodeMeasurementBuilder.m:132` vs `:181`; `MeasurementModel.m:89-124`). No truth variable appears in any `h` term.
- The EKF `predict`/`update` read only `obj.x`/`obj.P`; tower-clock objects handed to `predict` are consumed for their **process-noise spectrum only** (`getProcessNoiseQ` → `h`-coefficients), never their realised `bias_s`/`fracFreq`.
- The `sameAsTruth` atmosphere oracle is **forbidden** — it throws `revgnss:oracleTropModelResidual` / `oracleIonoModelResidual` (`EnvironmentModel.m:142-146,181-184`), a stronger guarantee than "default off".
- Truth noise is drawn from identity-keyed independent substreams `(src,node,ant,sig,epoch)`; the **EKF has no RNG at all** (grep-confirmed), so estimator randomness cannot correlate with any truth stream. `getMeasurementState`/`getReportEulerRad` return estimator state (the nominal quaternion, not `asset` attitude). Truth-only tide/EOP/PCO displacements shift `z` only and survive `z−h` as genuine unmodelled error.

**The one item — L2 (low):** `getGyroReading` returns the *truth* body rate when `obj.gyro` is empty (`SpaceAsset.m:193-194`). On the documented path this is unreachable (`imu.enable` builds the gyro *and* sets `estimateGyroBias`; with the default `estimateGyroBias=false` the accessor is never called). It becomes an oracle input only under the off-label combination `estimateGyroBias=true` + `imu.enable=false`. **Fix (V6-4):** make the accessor error/NaN instead of silently substituting truth.

## 6. IMU, attitude & nadir pointing — the headline gap

### 6.1 What the sim does today
The truth spacecraft attitude is a **constant Euler angle in ECEF** (`attitude_euler_rad`, default `[0;0;0]`), propagated by `angularRate_body_radps` (default `[0;0;0]`) through `SpaceAsset.propagate/propagateAttitudeAndClock`. With `euler=[0;0;0]` the body-to-ECEF DCM is the identity, so **body +X/+Y/+Z coincide with ECEF +X/+Y/+Z**. The receiver cross lies in the body XY-plane, so its face-normal is body +Z = ECEF +Z = the **North celestial pole**. For the equatorial GEO at lon 23°E, nadir is `−r̂ = [−cos23°; −sin23°; 0]` in the equatorial plane — **~90° away from where the array points.** The satellite flies a *pole-locked, Earth-fixed* attitude, held for the whole run because `ω=0 → euleṙ=0`. **This is finding H1, independently CONFIRMED.**

There is **no nadir/LVLH/RTN attitude anywhere in the sim path** (M2): a tree-wide search finds only `OrbitFrame`'s RAC basis (error-projection only, never fed to attitude) and a schematic plotting `Cnadir` never imported by the sim. `AttitudeKinematics` exposes only DCM/euler-rate/lever-arm/gimbal utilities — no pointing method. The boresight body axis is likewise undeclared in config (L6), so "point nadir" is under-specified until an axis is chosen.

### 6.2 The gyro (IMU) path
`GyroModel` is **clean and honest**: `ω_meas = ω_true + b(RRW) + white(ARW)` from a dedicated RNG, filter never sees the truth realisation. Its default sigmas — ARW `1e-4 rad/√s` = **0.34 °/√hr**, initial bias `1e-5 rad/s` = **2 °/hr**, RRW `1e-6` — sit squarely in the **tactical grade** band (high-end MEMS / FOG; Groves Table 4.1), and truth/filter sigmas are matched. **M1 (Earth-rate omission):** the gyro is handed the *ECEF-relative* rate (=0), but a real strapdown gyro senses *inertial* rate — a nadir-locked equatorial GEO rotates once per sidereal day, so a physical gyro would read ≈ `7.2921×10⁻⁵ rad/s` about the polar axis. The model omits this Earth-rate term (the constant exists as `Constants.EARTH_OMEGA_RADPS` but is unused by the gyro). Internally self-consistent (truth and EKF both use ECEF-relative ω), so it is a *fidelity* gap, not a divergence — but the "inertial strapdown" label is not faithful at GEO. All IMU code is **default OFF** (`imu.enable=false`), so these are inert until enabled.

### 6.3 Making nadir the default (V6-1) — the exact change and its golden impact
For a GEO fixed in ECEF, nadir `= −r̂` is a **constant** ECEF direction, so a nadir attitude is a **constant Euler angle** (no body rate needed in ECEF). Choosing body +Z = nadir (`−r̂`) and body +X = along-track, the ZYX triple for lon λ=23°E is verified to be **`[roll; pitch; yaw] = [−1.5708; 0; 1.9722] rad`** (column 3 of the resulting DCM equals `−r̂ = [−0.9205; −0.3907; 0]`). Pitch=0, clear of the gimbal singularity. (The exact triple is convention-dependent on the chosen boresight axis; the load-bearing fact is that nadir is **not** `[0;0;0]`.)

**Golden impact — the crucial detail.** Changing the default truth attitude is:
- **Measurement-neutral for the single antenna** (`nReceivers=1`, lever arm `[0;0;0]`): `applyLeverArm` returns `r_cm + C(euler)·0 = r_cm` regardless of attitude, so `z`/`h` are unchanged. The estimated position/clock nonetheless shift at the **~1×10⁻⁴** level, because the attitude state (carried even at `nReceivers=1`, unobservable) couples weakly into the position/clock blocks through the shared joint covariance (the full-matrix PSD/SPD guard). The single-antenna golden is therefore kept byte-identical by **pinning it to the fixed `[0;0;0]` attitude** in `goldenScenarioConfig` — the same treatment its `templateSource='legacy'` and `nTowers=5` pins already use to insulate it from default drift.
- **A real change to the 4-antenna headline & realism goldens** (`nReceivers=4`, non-zero lever arms): a nadir attitude rotates every antenna phase centre → carrier/code/Doppler observables change. These goldens adopt the nadir default and are re-frozen.

Since the resolved default is `nReceivers=4`, the **default run is a 4-antenna attitude scenario** — so before this change it was demonstrating recovery of an *Earth-fixed pole-locked* attitude, not a nadir-pointing one. The estimator machinery is sound; only the truth scenario was unrealistic. **The 4-antenna golden move is deliberate, not a break to avoid** — keeping those byte-identical would mean the change had no physical effect.

**V6-1 as implemented:** added `AttitudeKinematics.nadirEulerFromEcef(r_ecef, v_ecef, boresight_body)` (builds the LVLH DCM with body +Z → −r̂, body +X → along-track, extracts the ZYX Euler); the nadir compute lives in `masterConfig`'s **runtime body** (after the `baseOnly` early-return), with the `attitudePointing`/`boresight_body` fields seeded `'fixed'` in `i_baseDefaults`. That split is deliberate: `ConfigFactory.defaultConfig` (= `masterConfig('baseOnly')`) and the ~20 derived/test configs keep the fixed `[0;0;0]` attitude, so the attitude unit tests stay green, while `run_oo_v1` and the goldens (full `masterConfig`) get nadir. Verified: default attitude → **0.000000°** from nadir (vs 90° before); the GEO's nadir direction moves <0.01°/day so the constant Euler is an effective lock (per-epoch tracking for moving orbits is a follow-up). Single golden pinned fixed (byte-identical); headline + realism re-frozen; the flagged `test_stage14_9` and the attitude/IMU/fleet unit tests pass. (Care points: nadir must NOT live in `i_baseDefaults` or it leaks to every test; the `attitudePointing`/`boresight_body` fields must be seeded there so `cfg.asset`/`cfg.assets` share a field set for `MultiAssetConfig.normalize`.)

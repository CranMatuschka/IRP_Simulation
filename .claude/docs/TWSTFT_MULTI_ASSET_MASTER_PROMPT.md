## Primary objective

Implement a scientifically coherent path from the current one-way reverse-GNSS simulator toward:

1. **Multi-asset space simulation** — multiple represented spacecraft, then optional joint estimation of multiple spacecraft states.
2. **Inter-satellite link (ISL) aiding** — the main estimated space asset receives RF observables and/or navigation-message information from other space assets.
3. **Two-way ISL / enhanced time transfer** — event-driven two-way time-transfer measurements between moving assets, without assuming symmetric propagation unless that assumption is explicitly configured and validated.
4. **TWSTFT** — Two-Way Satellite Time and Frequency Transfer between ground stations through a relay/transponder spacecraft, initially code-based, then carrier/frequency-transfer capable.
5. **Kalman-filter integration** — all new observables must enter through clear measurement builders, state ownership, row metadata, covariance semantics, gauge/observability checks, and finite-difference Jacobian tests.

This must be an evolutionary implementation, not a rewrite. Add interfaces and scenario flags first; enable physical measurement rows only after source-truth gates, unit tests, and report wording are in place.

## Important distinction: ISL information vs ISL observables

When the main space asset "gets ISL information", model two separate data paths:

### 1. RF observables generated by the link

These are measurements made by the receiving asset from the transmitted waveform:

- one-way code/pseudorange,
- one-way carrier phase,
- one-way Doppler/range-rate,
- two-way range and/or two-way Doppler,
- carrier beat/frequency-transfer readings,
- signal quality metadata such as C/N0 or lock indicators.

These become ordinary EKF measurement rows with `z`, `h(x)`, `H`, `R`, and row descriptors.

### 2. Navigation/telemetry payload carried inside the ISL message

These are data fields transmitted over the link, not raw measurements themselves:

- transmitting asset ID and receiver endpoint ID,
- transmit time tag in the transmitter clock,
- receive time tag in the receiver clock if returned in a two-way exchange,
- signal/channel ID, sequence counter, and message latency,
- transmitter ephemeris/state estimate and covariance,
- transmitter clock bias/drift estimate and covariance,
- transmitter attitude and antenna phase-center metadata if available,
- health/status flags, lock state, and quality indicators,
- calibrated TX/RX processing delays and their uncertainties,
- optional product epoch and product-age metadata.

Payload information can be used in three ways: as metadata supporting the RF observable, as pseudo-measurements on the secondary asset state/clock, or as a prior/product provider for the secondary asset. Never mix these roles implicitly.

## Kalman-filter state strategy

Implement in increasing complexity.

### Phase A: primary-only EKF with represented helpers

The secondary asset and relay are truth/represented-only. Their states may be supplied by truth, synthetic product providers, or fixed error models. EKF state remains the primary asset plus receiver clock states. ISL rows update only the main asset and its receiver clock.

Use this for first one-way ISL code/Doppler and two-way ISL range rows.

### Phase B: joint multi-asset EKF

Augment the state with selected secondary assets:

```text
x = [ asset_1_state ; asset_2_state ; ... ; shared_or_link_states ]
asset_i_state = [ r_i, v_i, attitude_error_i, omega_i, b_i, d_i ]
```

For each ISL measurement, apply partials to both receiver and transmitter asset columns:

```text
rho = || r_rx(t_rx) - r_tx(t_tx) ||
H_r_rx = +u^T
H_r_tx = -u^T
H_b_rx = +1
H_b_tx = -1
```

Doppler and event-time partials may initially use a finite-difference audit, but production code should move toward analytic geometry partials after validation.

### Phase C: link-specific nuisance states

Add only when observability permits:

- ISL carrier ambiguities per link/signal/arc,
- station modem delay biases,
- asset TX/RX processing delay residuals,
- transponder group delay residual,
- relay local oscillator frequency/phase state,
- common-mode session bias for TWSTFT code,
- frequency-transfer bias for carrier TWSTFT.

Every nuisance state must have a process model, units, prior covariance, report description, and observability guard.

## Measurement models to implement

### One-way ISL code

Use a transmit asset and receive asset endpoint:

```text
z_code = rho(t_tx, t_rx) + b_rx(t_rx) - b_tx(t_tx)
         + d_hw_rx - d_hw_tx + d_signal + epsilon_code
```

Start with vacuum/space link. Add atmospheric terms only for ground-space legs in TWSTFT. For space-space ISL, atmosphere should normally be absent unless a special near-limb propagation mode is configured.

### One-way ISL Doppler

```text
z_dopp = rho_dot + d_rx - d_tx + oscillator/link-rate terms + epsilon_dopp
```

The row must state whether it is in m/s or Hz. Avoid mixed unit conventions.

### One-way ISL carrier

```text
z_phi_m = rho + b_rx - b_tx + lambda*N_link_signal_arc
          + phase_center_terms + phase_windup_terms + epsilon_phi
```

Carrier must be diagnostic-only until ambiguity states and cycle-slip/arc management exist. Once enabled, ambiguity columns are mandatory.

### Two-way ISL time transfer

Do not use a simplistic same-epoch cancellation as the physical implementation. Build forward and return events explicitly:

```text
A tx at local time t_A_tx
B rx at local time t_B_rx
B tx at local time t_B_tx
A rx at local time t_A_rx
```

Include known TX/RX processing delays and solve light time for each leg. The measurement may be an estimated clock offset, two-way range, or round-trip delay, but the builder must retain the primitive event metadata. For moving assets, the two directions are not identical unless a special static/symmetric mode is intentionally selected.

### TWSTFT code

For ground stations A and B and relay/transponder S, generate simultaneous or scheduled transmissions:

```text
A -> S -> B
B -> S -> A
```

Each receive modem observes the remote signal and often the own returned/looped signal depending on the session mode. Model:

- uplink and downlink light times,
- station clock biases and drifts,
- station modem TX/RX processing delays,
- relay/transponder group delay,
- relay local oscillator effect if frequency translating,
- troposphere/ionosphere for ground-space legs when configured,
- common-mode cancellation residuals.

The filter may estimate station clock offset/frequency difference, primary asset clock, relay transponder delay, or treat some of these as calibrated products. The clock gauge must be explicit.

### TWSTFT carrier/frequency transfer

Implement after code TWSTFT is stable. Required modeled information:

- carrier counters referenced to local station clocks,
- received own and remote carrier readings at both stations,
- relay local oscillator frequency state,
- range-rate compensation for uplink/downlink Doppler,
- station frequency error between clocks,
- carrier thermal noise and counter noise,
- covariance from shared relay oscillator uncertainty.

A carrier TWSTFT session should first estimate or constrain the relay local oscillator/frequency translation, then solve frequency transfer. Do not claim convergence from four carrier readings alone unless tests demonstrate it.

## Covariance and correlation rules

- Never append only diagonal R if rows share a station clock product, relay LO, transponder delay, or session bias.
- Add block covariance helpers for:
  - shared transmitter clock product error,
  - shared receiver clock product error,
  - shared transponder delay,
  - relay local oscillator frequency error,
  - station modem calibration error,
  - session common-mode code error,
  - carrier ambiguity/cycle-slip arc status.
- Check all R matrices for symmetry and positive definiteness or positive semidefiniteness as appropriate.
- Add jitter only through one documented helper.
